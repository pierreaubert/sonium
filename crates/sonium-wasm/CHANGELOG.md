# Changelog

## Unreleased

## 0.5.0
### Fixed

- Binaural rendering applied every source's HRTF gain to the summed ear
  field; gains now apply per-source before summation (via the
  solver-method-aware `calculate_source_field`). Single-source output is
  unchanged; two identical sources now preserve ILD.
- The hybrid modal/ISM crossover used a per-frequency Sabine RT60, making
  the crossover itself frequency-dependent. All five blend sites now share
  one broadband Eyring-based `broadband_schroeder_frequency`, matching the
  room-data path.
- `bem`/`hybrid-bem` with an explicit wall-impedance table was silently
  solved with default boundaries; validation now rejects it loudly.
- `run_simulation`/`compute_frequency_point` indexed the first listener
  inside rayon closures; an empty listener list now fails as `JsValue`
  before the sweep instead of panicking a worker.

### Added

- Machine-adaptive rayon gates (`ParallelPolicy`): the frequency sweep and
  spatial slices parallelize when `work_items >= items_per_thread ×
  available_parallelism` (`SWEEP_ITEMS_PER_THREAD` /
  `SLICE_CELLS_PER_THREAD` starting grains,
  `SONIUM_ROOMSIM_PAR_THRESHOLD_SWEEP` /
  `SONIUM_ROOMSIM_PAR_THRESHOLD_SLICES` overrides, `SONIUM_SERIAL` escape
  hatch) — fixed constants cannot be right per machine. Small problems run
  the identical closures serially.
- `WallMaterialConfig::has_impedance` helper behind the BEM rejection.
- `tests/wasm_review_20260904.rs`: binaural ILD linearity, slice
  solver-method provenance, BEM-plus-impedance and zero-damping rejection,
  hybrid finiteness/determinism.
- Documented the slice contract (method-aware field, provenance method) on
  `compute_slices`.

### Changed

- Refreshed stale `AGENTS.md` (version 0.4.1, full module list, thresholds,
  contracts).

## 0.4.1

### Added

- `room_simulator_bem` and `room_simulator_fem` native binaries for BEM and FEM room simulations driven by JSON configs (the same configs the WASM build consumes from the browser). Enables full-stack regression testing of the room-sim path without rebuilding the WASM artefact every iteration.

## 0.4.0

### Added

- Test suite reorganised into three explicit categories: unit tests (`cargo test --lib`), accuracy tests (validation against analytical references), and performance tests (timing-gated benchmarks). Each tier has its own gating policy.
- Reference JSON configs checked in under `configs/`:
  - `example_lshaped_fmm.json` — L-shaped room with FMM BEM
  - `example_multi_source.json` — multi-source room
  - `example_rectangular.json` — rectangular shoebox
  - `home_theater_2_0.json`, `home_theater_2_1.json`, `home_theater_5_1_4.json` — representative home-theatre layouts
  - `lshaped_stereo.json`, `nearfield_stereo.json`, `nearfield_stereo_vis.json`
  - `stereo_2_1_example.json`, `stereo_2_1_directivity_example.json`
- Modular split of the simulator: `acoustics`, `adaptive`, `bem_solver`, `loaders`, `room_modes`, `scattering_objects`, `worker_detect`. Presentation assets are generated by the deterministic `web_gallery` example rather than a library `plotting` module.
- WASM build pipeline: `build-wasm.sh`, `wasm-bindgen-rayon` parallelism, and `wasm-opt` post-pass for release builds.
- Nginx deployment recipe under `etc/nginx/spinorama-roomsim`.

### Notes

- WASM builds must disable the `native` feature on `sonium-bem` and enable its `wasm` feature.
- The library compiles to both `cdylib` (for the browser) and `rlib` (for the native binaries).
